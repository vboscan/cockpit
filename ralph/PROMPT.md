You are one iteration of an autonomous implementation loop for cockpit. Rules: `AGENTS.md` + `CLAUDE.md`. Architecture: `PLAN.md`.

## Preconditions (check, don't assume)

- **The front is not yours.** `scripts/ralph-iterate.sh front` has already run preflight, picked the spec, resumed or created the branch, sliced the spec, had red written, observed it red, committed `checkpoint(red)` and passed the plan review. Your prompt names the spec, slice, branch and resume point; `.ralph/handoff` repeats them. Do none of those steps yourself, and never launch red or a plan review.
- **No hand-off in your prompt?** A human started you: run `scripts/ralph-iterate.sh front --attended` (in the background — it lasts as long as red does) and follow what it prints. If it exits non-zero, STOP — its message is the reason and the owner is already notified. (Design-gate phase, driver `-p DESIGN_GATE_REACHED`: there is no front; run `scripts/preflight.sh` yourself and STOP if it fails.)
- Hand-off `RESUME=iteration-zero`: run `ralph/ITERATION-ZERO.md` now; if it fails, STOP and follow its unblock procedure.
- **Owner gates** and **supervised specs** are the front's to enforce: it stops before you exist. A human ticks a gate, never an iteration.

## Iteration

1. Read `PROGRESS.md`, then **only** the hand-off's spec plus any it names in `Depends-on`, with `specs/00-conventions.md`, the spec's slice file under `ralph/` and the plan. Never read all of `specs/` (~15K tokens; LESSONS §1).
2. You are on the hand-off's branch, already rebased. `RESUME` says where to pick up — `red` → implement to green; `green` → run the gates, minus any `scripts/gate-marker.sh check <gate>` clears; `gated` → PROGRESS.md + PR. Build the hand-off's slice and nothing else (LESSONS §2).
3. **Green via the `tdd` skill** (seams pre-agreed by the spec's Deliverables). The red tests are on the branch at `checkpoint(red)`: written by a fresh session, observed red and committed by the script, plan-reviewed (LESSONS §4). Implement until green. You may *add* tests; you never modify or delete a red test without a `Test-Amendment:` trailer naming it and the reason; a red test that contradicts the spec is an escalation, not an edit (`scripts/drift-check.sh` enforces both at merge). Mechanical sub-tasks may go to `scripts/agy-task.sh` (AGENTS.md rule 8; `agy-delegation` skill; LESSONS §3) — never tests, design, debugging or security code; exit 75 = agy unavailable, do it inline. Keep tool output out of context: suite and sweep output through `| tail -40` or to a file.
4. Full suite + lint + typecheck, all green, no skips. **`checkpoint(green): <spec> <slice>`** — the state the gates read.
5. Run the three reading gates — `/security-review`, `/code-review`, `/code-review-relative-to-specs` — **always as fresh headless sessions on the review tier**, `scripts/claude-run.sh <gate> <NN> <slice> -- -p --model $RALPH_REVIEW_MODEL "/<gate>"` (15-minute timeout each; every headless call goes through `claude-run.sh` so the usage ledger sees it), **one at a time** (LESSONS §5). Review is independent, never inline (AGENTS.md rule 8). For the specs `specs/00-conventions.md` lists as adversarial, also run the adversarial-additions session: `scripts/claude-run.sh adversary <NN> <slice> -- -p --model $RALPH_REVIEW_MODEL "Given specs/<NN> and this green tree, write attack tests (tampered proof, replayed frame, snapshot from the wrong epoch, resumed leader, malformed bytes) as additions only, in test files only"` — it may change test files and nothing else (exit 3 as in step 3); you run them, commit them, and fix what they find. Then `/verify` **inline in this session** — drive the changed behaviour end-to-end; it includes the mutation run on the packages `specs/00-conventions.md` names, to at least `RALPH_MUTATION_FLOOR`, and the fuzz targets it names for a fixed budget. Findings are failing tests: fix, or record explicit acceptance with a reason in PROGRESS.md. Unresolved findings = not done.
   **Mark each gate as it lands**: commit the fixes, then `scripts/gate-marker.sh record <gate> <spec> <slice>` (`security-review` | `code-review` | `code-review-relative-to-specs` | `verify`); it refuses on a dirty tree. On resume, `scripts/gate-marker.sh check <gate>`: exit 0 → skip, exit 1 → run. Skips are authorised by the script, never by eye.
   **Confirm the fixes**: one scoped pass after the last gate's findings are fixed — `scripts/claude-run.sh confirm <NN> <slice> -- -p --model $RALPH_REVIEW_MODEL "/code-review — scope: git diff <checkpoint(green) sha>..HEAD only. For each finding below, state whether the fix actually resolves it, and flag anything the fix introduces: <findings>"` — and re-run the suite. Skip only when there is no delta. **At most two confirm rounds per slice**; after round 2, record what remains as *accepted* with a reason, or re-slice — **except a `/security-review` finding, which is never accepted: stop and notify for a human.**
   **`checkpoint(gated): <spec> <slice>`** once all gates are clean or accepted and the confirm pass came back clean (`--allow-empty` when nothing changed).
   **Tail order is fixed**: confirm pass → `checkpoint(gated)` → step 6 (push, PR, PROGRESS.md entry, commit) → `scripts/gate-marker.sh record confirm <spec> <slice>` → `assert-complete` → merge. The `confirm` marker is recorded LAST and vouches for the exact tree that merges.
6. **Push and open the PR FIRST**: `git push -u origin <branch>` (retry 4× with 2s/4s/8s/16s backoff), then `scripts/open-pr.sh --title "<type>(<NN>): <title>" --body-file <path>` — the scope names the spec for `scripts/progress-sync.sh`. Take `#<N>` from what it prints and nowhere else; never a predicted number, never `#TBD` (LESSONS §6). **Then** `scripts/usage-session.sh implement <NN> <slice>` (records this session's tokens in the ledger), and update `PROGRESS.md` once: spec status (`in-progress (slice K/M)` names the slice this PR merges — the front reads it to pick the next), what changed, decisions, accepted findings, next. `done` means merged, never "code written". **Rotation**: rows that became `done` move to `PROGRESS-archive.md`; keep the newest 3 log entries here and move older ones there; Notes ≤ 60 chars. If a mechanical-shaped delegation opportunity existed, add one line starting with the literal marker `**Delegation**:` — `delegated <what> (<tier>)` or `skipped <what> because <reason>`.
7. **One commit on `main`**: the squash-merge collapses the checkpoints. When CI is green, `scripts/merge-pr.sh <N>` as a **bare command**, never chained with `cd`/`&&`/pipes, or the allowlist misses and the classifier denies it (LESSONS §7) (it runs `assert-complete`, `drift-check.sh`, `progress-sync.sh` and `hot-path-check.sh`; a refusal names what to fix: fix it on the branch, commit, push, wait for green, run it again). The iteration is complete ONLY when the merge has landed on `main`. **A merged branch is dead**: switch to `main`, delete the branch locally (origin deletes it at merge), never commit to or resume from that name again; new work starts a new branch off fresh `main` (LESSONS §7).
8. **Notify (non-blocking)**: `scripts/explain-iteration.sh <N> specs/<NN>-*.md <merge-commit>` (the plain-language summary, posted to the PR and to the notifications issue), then `scripts/notify.sh` with spec + one-line summary + PR link + this prompt:
   > For cockpit iteration <N> (spec <NN>, PR #<X>): give me step-by-step manual test instructions to try the behavior myself.
   > If either sending fails, log it in PROGRESS.md and continue — never block on notification.

## Loop driver

`scripts/ralph-driver.sh`, supervised by `scripts/ralph-heartbeat.sh` — start the **heartbeat** in its own tmux, named per project so two kits on one box do not collide: `tmux new -As ralph-<project> 'scripts/ralph-heartbeat.sh'` (`RALPH_TMUX_SESSION`). Each cycle runs the front (`scripts/ralph-iterate.sh`; exit 11 = it stopped for the owner, no strike), then spawns a **fresh** session (`scripts/claude-session.sh`, model per AGENTS.md rule 8), sends the hand-off prompt, waits, kills it. **One session = one iteration = no carried context**; state persists via `PROGRESS.md`/git only. Completion is judged by `origin/main` advancing. Ceiling `RALPH_ITER_TIMEOUT` (default 2h); cancel with `touch ralph/STOP`. A *merit* no-merge exit counts toward the 2-strike breaker; a *limit* exit yields to the supervisor (probe every 10 min, ≤ 3 relaunches per 24h). Details and reasons: LESSONS "Loop driver".

Phases: **1** — promise `DESIGN_GATE_REACHED` once iteration zero shows PASSED and the design kickoff is delivered; **2** — promise `ALL_SPECS_DONE` only when every `specs/` entry is `done`. Only output a promise when it is unequivocally true — never to escape the loop.

## Failure handling

- Tests can't pass / spec ambiguous or contradicts PLAN.md: don't force it. Write the blocker + a proposed spec amendment to PROGRESS.md, stop cleanly with no partial merge.
- Never push directly to `main`; never merge with red CI; never mark a spec done with unresolved review findings.
